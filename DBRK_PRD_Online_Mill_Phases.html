DBRK Online × ระบบโรงสี

วางวิธีทำงานให้ขายออนไลน์ได้หลักพันออเดอร์ต่อเดือนโดยไม่คีย์ซ้ำ แบ่ง 2 ระยะ: Phase 1 ใช้ระบบเดิมของโรงสี (Express + Access) ต่อไปโดยไม่ต้องนำเข้าไฟล์ · Phase 2 เปลี่ยนบัญชีเป็น FlowAccount และย้ายระบบหน้าโรงสีออกจาก Access

สรุประบบวันนี้หลักการPhase 1Phase 2คำถามที่ต้องตอบทำอะไรต่อ

สรุป

Phase 1 · ใช้ระบบเดิม

คีย์ยอดสรุป ไม่คีย์รายออเดอร์

ระบบ Online ทำงานรายออเดอร์ทั้งหมด แล้วออกแผ่นคีย์ให้บัญชีคีย์ IV สรุปต่อแพลตฟอร์มต่อสัปดาห์ และใบรับชำระต่อยอดเงินเข้า จาก ~1,000 IV/เดือน เหลือ ~20–30 ใบ

Phase 2 · FlowAccount + ระบบโรงสีใหม่

ไม่มีคนคีย์เอกสารขาย

ระบบส่งเอกสารขายและรับชำระเข้า FlowAccount ผ่าน API · ใบชั่ง บิลขาย ลูกหนี้หน้าโรงสี และสต๊อก 2 คลัง อยู่ฐานข้อมูลเดียวกับ Online

ต้องตอบก่อน

ขายข้าวมี VAT หรือไม่

Express ตั้ง IV ของ TikTok เป็น “ไม่มี VAT” แต่ระบบ Online ตอนนี้คิด VAT 7% ในเอกสาร การออกเอกสารอัตโนมัติยังปิดอยู่จนกว่าบัญชีจะยืนยัน

1 · ระบบวันนี้

จากภาพหน้าจอที่ได้มา มี 4 ที่ที่เกี่ยวกับการขายออนไลน์ และ 1 ออเดอร์ถูกบันทึกด้วยมืออย่างน้อย 1–2 ครั้งนอกแพลตฟอร์ม

ระบบใช้ทำอะไรสิ่งที่เห็นในภาพ

ระบบ Online (DBRK)ดึงออเดอร์ เงิน สต๊อก แพ็ก เอกสารPhase 2 (ท่อน ①) กำลังทดสอบบน preview
Access (หน้าโรงสี)ใบชั่ง ขายหน้าโรงสี ลูกหนี้หน้าโรงสีทะเบียนลูกหนี้มี “Tiktok Shop” “Shopee” “ขายปลีก” · รายงานขายหน้าโรงสียังไม่ตัดบัญชีของ Tiktok Shop เป็นรายใบชั่ง หลายรายการราคา 0 · ยังไม่มีรายการจ่าย
Express (บัญชี)บัญชีทางการ ลูกหนี้ สต๊อก ภาษีIV ขายเงินเชื่อ ลูกค้า C777 Tiktok shop · ชื่อผู้ซื้อในช่องอ้างอิง · สินค้า 00-1005-08 ดอกบัวหอม 5 กก. 310 บาท + ของแถม 00-1002-08 F=Y ราคา 0 · คลัง 01 · ขนส่ง J&T · ประเภทราคา “0 - ไม่มี VAT”

สิ่งที่ต้องแก้ · (1) ยิ่งขายมาก งานคีย์ IV ยิ่งมาก เพราะคีย์ต่อออเดอร์ · (2) เงินเข้าเป็นก้อน ไล่ตัดลูกหนี้กับ IV หลายร้อยใบด้วยมือแทบไม่ได้ · (3) ลูกหนี้ Tiktok/Shopee อยู่ทั้งใน Access และ Express อาจนับซ้ำ · (4) ระบบ Online คิด VAT 7% แต่ Express ตั้งไม่มี VAT

2 · หลักการ (ใช้ทั้ง 2 phase)

  • ข้อมูลแต่ละอย่างมีเจ้าของที่เดียว ที่อื่นรับต่อเป็นยอดสรุป

  • ทุกยอดที่ข้ามระบบมีเลขอ้างอิงทั้งสองฝั่ง เลขชุดขายอยู่ใน Express · เลข IV/ใบรับชำระอยู่ในระบบ Online

3 · Phase 1 — Online + ระบบเดิม

เริ่มได้ทันทีเมื่อได้คำตอบ Q1–Q4

Express นำเข้าหรือส่งออกไฟล์ไม่ได้ และบัญชีโรงสีทำงานในเครื่องเดียวกัน (Remote Desktop) จึงให้ระบบ Online ทำงานรายออเดอร์ทั้งหมด แล้วส่งยอดเข้า Express ผ่าน “แผ่นคีย์” ที่เรียงช่องตามหน้าจอ Express ให้คีย์ได้เร็ว

เป้าหมายและวิธีวัด

เป้าหมายวัดอย่างไร
เลิกคีย์ IV ต่อออเดอร์เอกสารที่คีย์ใน Express ต่อเดือน ≤ 40 ใบ ที่ 1,000 ออเดอร์
ลูกหนี้แพลตฟอร์มตรงกันทุกเดือนหน้าเทียบลูกหนี้สิ้นเดือน ต่าง 0 หรือมีรายการอธิบายครบ
สต๊อกออนไลน์ปิดยอดกับ Express ได้สิ้นเดือน ยอดติดลบที่ยังไม่มีเลข IV = 0
รู้ว่าเงินแต่ละก้อนมาจากออเดอร์ไหนเงินเข้าทุกก้อนในเดือนจับคู่แล้ว 100%

ไม่อยู่ใน Phase 1

  • เชื่อม Express อัตโนมัติ (Express นำเข้าไฟล์ไม่ได้)
  • แก้ฟอร์มหรือรายงานใน Access
  • ยื่นภาษี / e-Tax Invoice (บัญชีโรงสียื่นในนามบริษัทเหมือนเดิม)
  • เขียนสต๊อกกลับแพลตฟอร์ม (ยังเป็นไฟล์ให้ทีมอัปโหลดเอง)

ใครทำอะไร

คนทุกวันทุกสัปดาห์สิ้นเดือน
ทีมแพ็กงานแพ็กวันนี้ · พิมพ์รวม · กดแพ็กแล้ว——
แอดมิน Onlineดูแจ้งเตือน SKU ยังไม่ผูก · ขายช่องทางอื่นนำเข้า statement · จับคู่ที่ไม่ตรงติ๊กตรวจรับเงินให้ครบ
บัญชีโรงสี—คีย์ IV สรุป + ใบรับชำระ ตามแผ่นคีย์ · กรอกเลขกลับส่งปิดงวด · เทียบลูกหนี้ · คีย์ค่าใช้จ่าย
คุณขวัญDashboard—อนุมัติปิดงวด

ขั้นตอนการทำงาน

ภายนอก / คนระบบ Onlineหน้าโรงสีบัญชีกรอบเส้นประ = รอยืนยัน

สิ่งที่ต้องสร้างเพิ่มในระบบ Online

ข้อระดับทำอะไรผ่านเมื่อ
R1P0แก้วิธีคิด VAT ให้ตรงกับคำตอบ Q1 (ถ้าไม่มี VAT: เอกสารผู้ซื้อเป็นใบเสร็จรับเงิน/ใบส่งของ · ยอดไม่แยก VAT · ชุดปิดงวดไม่มีแผ่นภาษีขาย)เอกสารและรายงานตรงกับ Express ทุกบาท
R2P0รหัสสินค้า Express ต่อสินค้าหลัก + รหัสลูกค้า Express ต่อช่องทาง (หน้า ตั้งค่า Online)ทุก SKU ที่ขายได้มีรหัส Express · ขาดแล้วออกแผ่นคีย์ไม่ได้
R3P0ชุดขาย: จัดกลุ่มออเดอร์ที่แพ็กแล้วตามแพลตฟอร์ม + รอบ (วัน/สัปดาห์/เดือน) · ยกเลิกหลังเข้าชุดเป็นรายการลดในชุดถัดไปทุกออเดอร์ที่แพ็กอยู่ในชุดเดียวเท่านั้น
R4P0แผ่นคีย์ IV เรียงตามหน้าจอ IV ขายเงินเชื่อ (รวมของแถม F=Y)ยอดรวมแผ่น = ผลรวมออเดอร์ในชุด
R5P0ช่องกรอกเลข IV ต่อชุด → ล็อกชุด + บันทึก “ปิดยอดกับ Express” คืนสต๊อกสต๊อก Online = −(ถุงในชุดที่ยังไม่มีเลข IV)
R6P0แผ่นคีย์รับชำระต่อยอดเงินเข้า: ตัด IV เลขไหนเท่าไร + ค่าธรรมเนียม · ช่องกรอกเลขรับชำระกลับผลรวมที่ตัด + ค่าธรรมเนียม = ยอดก่อนหัก
R7P0โหมดสต๊อกเริ่ม 0 ติดลบได้ · หน้าเทียบลูกหนี้สิ้นเดือนทดสอบปิดงวดจริง 1 เดือน
R8P1ไฟล์สต๊อกแพลตฟอร์มใช้ยอดคลังโรงสีที่กรอกสัปดาห์ละครั้ง (เพราะยอด Online เป็น 0/ติดลบ)ไม่ตั้งขายเกินของที่โรงสีมี
R9P1ขายช่องทางอื่น (LINE/โอนตรง) เข้าแผ่นคีย์เป็นลูกค้า “ขายปลีก” ของ Expressยอดขายช่องทางอื่นอยู่ใน Express ครบ

ความเสี่ยงของ Phase 1

  • ยังมีการคีย์ด้วยมือ (ราว 20–30 ใบ/เดือน) จึงพิมพ์ผิดได้ → หน้าเทียบลูกหนี้จับได้ภายในเดือนนั้น
  • ถ้า Access ยังตั้งลูกหนี้ Tiktok/Shopee ต่อไป ยอดลูกหนี้จะอยู่ 2 ที่ (Q3)
  • สต๊อกจริงอยู่ที่ Express เท่านั้น ระบบ Online เห็นแค่ยอดที่ยังไม่ปิด จนกว่าจะถึง Phase 2

4 · Phase 2 — Online + FlowAccount + ระบบโรงสีใหม่

ต้องสำรวจงานใน Access ก่อนประเมินราคา

เปลี่ยนบัญชีจาก Express เป็น FlowAccount ซึ่งมี Open API สำหรับสร้างเอกสารขาย ใบเสร็จ ใบวางบิล และใบสั่งซื้อ (ต้องขอสิทธิ์ใช้ API ก่อน) และย้ายงานหน้าโรงสีจาก Access มาอยู่ระบบเดียวกับ Online เพื่อให้ลูกค้า สินค้า สต๊อก และเงิน อยู่ฐานข้อมูลเดียว ไม่ต้องคีย์ซ้ำทั้งออนไลน์และหน้าโรงสี

โครงระบบ

เป้าหมายและวิธีวัด

เป้าหมายวัดอย่างไร
ไม่มีการคีย์เอกสารขาย/รับชำระด้วยมือเอกสารขายและรับชำระใน FlowAccount มาจาก API 100%
สต๊อกตรงของจริงทั้ง 2 คลังส่วนต่างนับสิ้นเดือน < เกณฑ์ที่ตกลง
ปิดงวดเร็วขึ้นปิดงวดเสร็จภายในวันที่ 3 ของเดือน
เลิกใช้ Accessหน้าโรงสีใช้ระบบใหม่ครบทุกงานที่ Access เคยทำ (ตามผลสำรวจ Q7)

ขั้นตอนการทำงาน

ภายนอก / คนระบบ DBRKโมดูลโรงสี / คลังโรงสีFlowAccount / บัญชีกรอบเส้นประ = รอยืนยัน

สิ่งที่ต้องสร้าง

ข้อระดับทำอะไรผ่านเมื่อ
R10P0ตัวเชื่อม FlowAccount: ขอสิทธิ์ API · ทดสอบบน sandbox ก่อน · ส่งซ้ำไม่เกิดซ้ำ · คิวลองใหม่ + แจ้งเตือน · บันทึกทุกคำขอส่ง 1 เดือนจริงบน sandbox ยอดตรง 100%
R11P0จับคู่ลูกค้า สินค้า บัญชี ระหว่างระบบ DBRK กับ FlowAccountไม่มีเอกสารที่ส่งไม่ได้เพราะไม่มีรหัส
R12P0โมดูลโรงสี: ใบชั่ง · บิลขายหน้าโรงสี · ลูกค้า + เครดิต · วางบิล · รับชำระ · รายงานลูกหนี้ (แทนฟอร์มและรายงาน Access เดิม)ทีมหน้าโรงสีใช้แทน Access ได้ 1 เดือนเต็ม
R13P0สต๊อกรวม 2 คลัง + ใบโอน (มีโครงอยู่แล้วใน Phase 2 ระบบ Online)ยอดคงเหลือ = ผลรวมการเคลื่อนไหว ทั้ง 2 คลัง
R14P0ย้ายข้อมูล: ลูกค้า สินค้า ยอดลูกหนี้ยกมา สต๊อกยกมา จาก Express + Accessยอดยกมาตรงกับงบปิดของ Express
R15P1อ่านยอดจาก FlowAccount มาเทียบอัตโนมัติ (ถ้า API ให้อ่านได้)หน้าเทียบไม่ต้องกรอกมือ
R16P1ต่อเครื่องชั่งเข้าระบบโดยตรง (ถ้าเครื่องรองรับ)ไม่ต้องพิมพ์น้ำหนักเอง

การย้ายระบบ

ช่วงทำอะไร
สำรวจ (2–3 สัปดาห์)นั่งดูงาน Access ทุกหน้าจอ/รายงาน · เลือกแพ็กเกจ FlowAccount · ขอสิทธิ์ API · สรุปขอบเขตและราคา Phase 2
สร้างและทดสอบโมดูลโรงสี + ตัวเชื่อม FlowAccount บน sandbox · ทดสอบกับข้อมูลจริงย้อนหลัง 1 เดือน
ทำคู่ขนาน 1 เดือนใช้ระบบใหม่จริง แต่ Express/Access ยังเปิดไว้เทียบ
เปลี่ยนจริงเริ่มต้นงวดบัญชี (แนะนำต้นปีบัญชีหรือต้นไตรมาส) · ยกยอด · Express/Access เหลืออ่านอย่างเดียว

ไม่อยู่ใน Phase 2 (เว้นแต่ผลสำรวจบอกว่าจำเป็น)

  • รับซื้อข้าวเปลือก การผลิต/สีข้าว เงินเดือน — ถ้า Access ทำงานเหล่านี้อยู่ ต้องประเมินแยก
  • ยื่นภาษีอัตโนมัติ (ทำใน FlowAccount ตามวิธีของบัญชี)

ความเสี่ยงของ Phase 2

  • ยังไม่ได้ตรวจรายละเอียด API FlowAccount (เส้นทาง ฟิลด์ ข้อจำกัดจำนวนครั้ง ระบบสต๊อก) ต้องได้สิทธิ์และเอกสาร API ก่อนยืนยันขอบเขต
  • Access อาจทำงานมากกว่าที่เห็นในภาพ (ซื้อข้าวเปลือก ใบชั่งซื้อ) ขอบเขตจะโตตามผลสำรวจ
  • ทีมหน้าโรงสีต้องเปลี่ยนวิธีทำงาน ต้องมีช่วงฝึกและทำคู่ขนาน

Q2ตอนนี้คีย์ IV 1 ใบต่อ 1 ออเดอร์จริงไหม ใครคีย์ ใช้เวลาเท่าไรบัญชีโรงสีPhase 1
Q3รายการ Tiktok Shop / Shopee ใน Access คืออะไร (ของที่ทีมออนไลน์เบิกไปแพ็ก? ของแจกครีเอเตอร์?) · เลิกตั้งเป็นลูกหนี้ใน Access ได้ไหมคุณขวัญ + หน้าโรงสีPhase 1
Q4คีย์ IV สรุปรอบไหน: รายวัน / รายสัปดาห์ (แนะนำ) / รายเดือนบัญชีโรงสีPhase 1
Q5ค่าธรรมเนียม ค่าส่ง ส่วนลดแพลตฟอร์ม ลงบัญชีอย่างไรในใบรับชำระบัญชีโรงสีPhase 1
Q6Express มีรหัสสินค้าครบทุก SKU ที่ขายออนไลน์ไหม (รวมแพ็คคู่ ดอกบัวหอม)บัญชีโรงสีPhase 1
Q7Access ทำอะไรบ้าง (ใบชั่งขาย/ซื้อ · ซื้อข้าวเปลือก · ลูกหนี้ · รายงาน) · ผู้ใช้กี่คน · เครื่องชั่งต่อคอมได้ไหมคุณขวัญPhase 2
Q8FlowAccount แพ็กเกจไหน · ใช้ระบบสต๊อกของ FlowAccount ไหม · ขอสิทธิ์ Open APIคุณขวัญ + ต้นPhase 2
Q9วันเริ่มใช้ FlowAccount (ต้นงวดบัญชีไหน)คุณขวัญ + บัญชีPhase 2
